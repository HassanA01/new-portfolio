# Aneeq — Style Guide

Personal portfolio for Aneeq and anyone visiting, human or agent.

## Direction

Simple, elegant, peaceful. Minimal cognitive load. Original and iterative; no reference sites. The homepage is a single screen at ordinary viewport sizes, with a centered, left-aligned content block. Preserve access to content at large text sizes and short viewports by allowing natural overflow.

## Typography

Manrope, self-hosted by Next.js. Heading: 40–48px, medium weight, tight tracking. Body: 16–18px, relaxed 1.8 line height. Navigation: 12px.

## Colors

Light: warm ivory-grey #f4f1e9, charcoal #262623, muted #62625c. A restrained yellow undertone softens the bright page surface; maintain readable text contrast. Hover #eae6dc, borders #dcd7cb.
Dark: near-black #191a18, off-white #eeeee8, muted #aaa9a1.
Borders and hover surfaces are subtle neutral tones. No decorative imagery. The input alone uses a subtle neutral gradient, translucent surface, and inset highlights for an Apple-inspired glass finish.

## Structure and interaction

Home, Blog, Gallery navigation and its theme toggle form a centered group above the content, with the toggle on the right. Homepage heading is “Hello 👋”. Introductory copy is exactly what Aneeq supplied. Agent mention remains plain text. Blog and Gallery have simple empty states until content is supplied.

Use device theme initially; persist manual theme selection. Provide visible keyboard focus, 44px touch targets, active page indication, and a 220ms theme transition. Touch-activated controls do not display keyboard focus rings. On phones, the top bar stays visible on Home and returns when scrolling up on About. Entrance motion is subtle and disabled for reduced motion. No scrolling effects or continuous animation.

LinkedIn and GitHub brand icons sit below the introduction. Use 20px monochrome icons inside links 32px wide and 44px tall, with no added gap; transition from muted to foreground on hover and keyboard focus.

The homepage has a bottom-centered rounded agent input with two compact suggestion buttons above it. Keep it in document flow so small screens and the mobile keyboard cannot obscure content. Until an agent is connected, submissions show an honest availability notice; the résumé shortcut also offers the existing PDF.

Input: 44px tall, composer max-width 520px, centered. Keep glass highlights restrained in both themes.

Suggestions use flatter surfaces and 12px corners to distinguish them from the glass input. A clipped, cursor-positioned highlight responds within each surface, without backdrop blur or React state updates. Disable reactive gloss for touch and reduced motion.

Quick replies: when Anike ends a reply with a decision (the `offerChoices` tool), two to four bare answers (“yes”, “no”, never “yes please”) stack as 44px options directly on top of the input at exactly the composer's width, touching each other and the composer with no gaps: only the top option keeps the 22px top corners and the composer squares its top corners while they show; each sits on the composer's own faint signature tint with a signature hairline that deepens on hover; the label sits left and a numbered `kbd` tag right on desktop (hidden on touch and under 600px). Clicking or pressing that number sends the choice as the visitor's message. They fade up in 220ms (off under reduced motion) and disappear as soon as the next reply starts.

Agent cards: each tool result is a first-class site component, never a generic label/detail list, and each borrows a colour story the site already tells. Any link inside a card (“the full journey ↗”, “more about me ↗”, the fact links) is set in the foreground colour with a hairline underline that darkens on hover; never muted. Career renders the About page's role rows condensed (22px logo, “Role @ **Company**” with the company name clipped in that company’s gradient, team in 12px muted, dates right-aligned at 11px) inside a 14px-radius hairline list; every row sits on its own company gradient (9%/6%, deepening on hover, strongest on the current role, which also carries a glowing dot before its dates) with the logo’s small rotate on hover. Rows are static: “the full journey ↗” under the list is the one way out to About. About sits on the “Currently @” purple-to-orange surface (light and dark variants), with a 44px portrait inside a 2px signature-gradient ring, the lede in intro typography, and “Currently” / “Education” / “Interests” / “Languages” rows (plain text, no links, no footer link) whose key nouns are clipped in that institution’s company gradient (Stripe purple-to-orange, UofT blue), the same variables the career rows use. Contact is a row of 38px link pills in the prompt-suggestion family, each brand mark filled with a nav-icon gradient pair and hovering into that pair’s tint; pills press to 0.92 on the spring. Résumé is a compact ticket on the pay button’s drifting signature gradient at 9% (16px radius, a signature-ringed icon tile beside an “open ↗” button carrying the full-strength drift, labelled for assistive tech). Only the button is interactive: no hover lift, a 0.95 press on `pressSpring`, and a slightly stronger border on hover. Project browsers deal their cards on first render: every card starts stacked on the top slot, each one scaled back 2.5% per depth, then drops into its row on a spring with a 70ms stagger; later filter changes keep the quieter 12px slide. No prices anywhere in chat. All of it is static under reduced motion.

Chat heading: the nav’s robot icon at 18px in its pink-to-gold Agent gradient, with “Anike” beside it in the foreground colour at 13px, weight 500.

Waiting: until the reply’s own words start streaming (it stays through reasoning and tool calls), a 40×24 Lissajous figure (x = sin 3t, y = sin 2t) sits where the reply will start, a hairline ghost of the curve underneath and a 2px point travelling it with a comet tail stroked in the signature gradient, looping every 2.6s. Reduced motion shows the full curve, still.

Activity rail: every agent reply starts with a 12px muted line describing the work (“finding my projects”, then “thought it through · searched my projects”). While the reply is live the label carries a monochrome shimmer and the rail is open; once it settles it collapses to one line with a chevron. Expanded, it reads like Claude’s own thinking block: reasoning summaries as muted prose and each tool call as one plain line (“searched my projects · category: All”) down a single hairline, no dots, no step titles, no chips; a failed call is named in red. No loading rows elsewhere; tool cards appear only when their output is ready.

Desktop homepage: shared 640px content width for introduction, current role, and composer; keep mobile fluid with existing gutters. About uses its independent reading column.

## Résumé checkout modal

The résumé icon opens a custom checkout dialog rather than Stripe’s embedded UI. 420px wide, 20px corners, same ivory surface and hairline borders as the homepage; no order summary, just the “My résumé” heading and Aneeq’s own one-liner, all lowercase with no full stop (“ain’t nun free in this world”). Our own email field sits above Stripe’s card fields, which are styled through Stripe’s Appearance API to match the site inputs (Manrope, 14px radius, 1px `--line` borders, muted focus border). The Payment Element uses the tabs layout, which hides the method picker when only card is enabled, so the card fields start straight at “Card number”. The pay button is 44px, ringed by a 1px border of the same signature gradient as its fill (masked, so corners stay round), 14px radius, filled with a soft four-stop signature gradient that drifts slowly (6s loop, paused when disabled, off under reduced motion). Hover eases it up to 1.03 (180ms, no bounce) and holds; pressing compresses it to 0.95 with `disclosureSpring`, held for as long as the press lasts. Close button is a 34px bordered square (10px radius) that springs on hover and tap with `disclosureSpring`; on hover the background fills with the résumé red and the X goes white. Success stays in the modal and drops the title: a signature-ringed check mark draws itself in the centre of the modal, holds a beat, then slides up to the top-left (shared layout spring); “Preciate dat cuz 🤞” and the receipt line fade in beneath it, with a shimmer placeholder in the download button’s footprint until the webhook confirms, at which point the button fades up over the placeholder (a 450ms CSS entrance, so re-renders can’t restart it). No retention note, return link, or “Powered by Stripe” footer on the confirmation; the footer only accompanies the payment form. Leaving after paying without clicking Download (backdrop click, the X, or Escape) raises the shared `ConfirmExit` prompt (the same component behind the chat’s “Leave this chat?”, each use passing its own copy and classes), here reading “bruv you didn’t download it yet. You sure you wanna exit?” with a ghost “Exit anyway” and a signature “Stay” button. That prompt is not dismissible: Escape or a click outside it shakes it (420ms, off under reduced motion) rather than closing it, so the buyer has to pick. A click on the download link clears the guard. Incomplete card details never raise a banner above the pay button; Stripe’s inline field error is the only message. Footer is just “Powered by Stripe”, 11px muted, with “Stripe” clipped in the same purple-to-orange gradient as the “Currently @” card. Entrance is a 220ms fade and lift, disabled for reduced motion.

Checkout loading reserves a stable payment-field region through session creation and Stripe iframe mounting. A subtle neutral skeleton stays visible until PaymentElement onReady, then the fields fade in over 240ms. Short screens scroll within the dialog; reduced motion disables pulsing and fading.

Homepage portrait: clicking flips the existing square through 180° over 650ms, plays the local inline video with audio from the tap gesture. A small top-right sound button allows muting and unmuting during playback. Playback end or a second click flips back. Keep the existing responsive portrait sizes and square cover crop. Load the animated WebP up front and request the video when playback starts. Reduced motion swaps faces immediately.

Projects: MailflowAI is the featured entry, with a fine signature-gradient outline curved into four subtle points. More projects sit in a native swipe-and-snap carousel with arrows and quiet pagination. Existing Manrope typography, real local project images, translucent theme-aware surfaces, and concise copy; no autoplay. Mobile shows one card plus a preview of the next.

Featured projects rotate manually among flwst8, Sawt and Hilal. Desktop uses wide previews with Cormorant Garamond titles, signature-lit pointed glass frames, arrows and pagination. Other projects become compact thumbnail rows on desktop; mobile retains stacked feature cards and a swipeable shelf. A slow border glow respects reduced motion.

Featured projects: on desktop (601px and up) the original pointed card stays exactly as it was, image beside copy, vertically centred. On phones a separate `FeaturedProjectMobile` renders the `FeaturedProject` template instead: a measured-pixel pointed frame (points and corners never stretch) with 40–44px of inner padding, then five fixed slots stacked (16:10 media, Cormorant title, blurb reserving three lines, up to six tech marks, 40px round links). Both are rendered and a media query shows one, so there is no script-driven switch or hydration flicker. On both cards the stack is drawn as brand marks (`TechMarks`, from simple-icons): bare 20px logos on 30px hit targets, no tiles or borders, each logo filled with a gradient from its brand colour to a lighter tint (near-black brands fall back to plain ink), on hover the logo tilts 10° with a small lift and scale on the same overshoot curve as the career-row logos, and the name appears in the mention popover; on desktop each mark links to the tool’s home page in a new tab. On touch layouts one tap opens a compact popup with a short description and an outbound arrow. Known technologies without a logo use a text pill. The project detail dialog uses the same marks. Phone swipes use native horizontal scroll snapping. Under “About me”, a 12px muted line shows the About content’s last revision date as a semantic time element. Customise the phone card through the template’s props (`blurb`, `maxTech`, `children`, `className`).

Projects discovery: About shows only the three featured projects, followed by a compact signature-tinted “Want to see more of my projects?” banner. “Explore with Anike” opens the existing ChatUI with a reusable ProjectExplorer already rendered. The browser uses the same FilterPill component as career filters (All, Web, AI/ML, Systems), compact project rows, and the existing detail dialog. The initial project entry is server-selected with `?explore=projects`; project questions in the simulated chat render the same component. Future agent tool outputs should pass a typed category into this component rather than generate markup. Filtering animates briefly and respects reduced motion; mobile rows fit without horizontal scrolling.

Anike streams replies directly from the configured Anthropic or OpenAI model, released one word every 24ms server-side (the AI SDK’s smoothStream) and each word fading up over 320ms as it lands; words already on screen never re-render, and reduced motion drops the fade. Prose is informal, all lowercase, with no em dashes. Typed server tools render the project browser, compact profile/career cards, and the existing résumé checkout modal. Project searches combine category, keyword/technology, year, and active/completed status. Missing metadata is explained rather than guessed. Project filters operate within the returned search results. Tool-loading states, honest empty states, retry, and stop controls use the existing muted palette and focus styles. The résumé tool never opens checkout by itself; the visitor taps the ticket's open button, and can do so again later from the message.
